# LPR — личные заметки

Веб-приложение для хранения личных заметок. Пользователь регистрируется по email,
входит в аккаунт и работает со своими заметками через браузер или REST API.

## Возможности

- Регистрация и вход по email и паролю.
- Создание, просмотр, редактирование и удаление заметок.
- Разграничение доступа: каждый пользователь видит только свои заметки.
- Даты создания и последнего изменения заметки.
- Веб-интерфейс на русском языке со списком заметок, отсортированным по времени изменения.
- Авторизация через JWT со сроком действия 30 минут и хеширование паролей Argon2.
- Интерактивная документация API.

## Локальный запуск

Понадобятся Python 3.12+, `uv` и Docker с Docker Compose. Все команды выполняются
из корня проекта. Docker Compose запускает PostgreSQL; приложение запускается отдельно.

### 1. Установить зависимости

```bash
uv sync --locked
```

Команда создаст виртуальное окружение `.venv` и установит зависимости из `uv.lock`,
включая инструменты разработки.

### 2. Настроить окружение

Если `.env` ещё не создан, скопируйте шаблон:

```bash
cp .env.example .env
```

Заполните `.env`:

```dotenv
DB_URL=postgresql+psycopg://root:root@localhost:5432/db1
SECRET_KEY=replace-with-generated-secret
```

Сгенерировать значение для `SECRET_KEY` можно так:

```bash
uv run python -c 'import secrets; print(secrets.token_hex(32))'
```

| Переменная | Назначение |
| --- | --- |
| `DB_URL` | URL подключения SQLAlchemy к PostgreSQL. Пример выше соответствует `docker-compose.yml`. |
| `SECRET_KEY` | Секретный ключ подписи JWT. Замените заглушку сгенерированным значением. |

Обе переменные обязательны. Настройки читаются из переменных окружения и файла `.env`;
переменные окружения имеют приоритет. Файл `.env` исключён из Git.
Учётные данные `root:root` в Compose предназначены для локальной разработки.

### 3. Запустить PostgreSQL и применить миграции

```bash
docker compose up -d postgres
docker compose exec postgres pg_isready -U root -d db1
```

Дождитесь ответа `accepting connections`, затем создайте таблицы:

```bash
uv run alembic upgrade head
```

Схема базы создаётся миграциями: запуск сервера сам по себе таблицы не создаёт.
Данные PostgreSQL сохраняются в Docker volume `postgres_data`.

### 4. Запустить приложение

```bash
uv run uvicorn backend.main:app --reload
```

После запуска доступны:

- [Веб-интерфейс](http://127.0.0.1:8000/)
- [Swagger UI](http://127.0.0.1:8000/docs)
- [ReDoc](http://127.0.0.1:8000/redoc)
- [Схема OpenAPI](http://127.0.0.1:8000/openapi.json)

Откройте веб-интерфейс и зарегистрируйтесь. После регистрации приложение автоматически
выполнит вход. Интерфейс раздаётся самим FastAPI и обращается к API на том же адресе;
отдельный сервер для `frontend` не нужен. Токен хранится в `localStorage` браузера.
По истечении срока действия токена потребуется повторный вход.

Для остановки приложения нажмите `Ctrl+C`, для остановки PostgreSQL выполните:

```bash
docker compose stop postgres
```

## API

Регистрация и получение токена доступны без авторизации. Все операции с заметками
требуют заголовок `Authorization: Bearer <access_token>`.

| Метод | Путь | Описание | Успешный ответ |
| --- | --- | --- | --- |
| `POST` | `/register` | Зарегистрировать пользователя | `201` |
| `POST` | `/token` | Получить JWT по email и паролю | `200` |
| `GET` | `/notes` | Получить все свои заметки | `200` |
| `POST` | `/notes` | Создать заметку | `201` |
| `GET` | `/notes/{note_id}` | Получить свою заметку по ID | `200` |
| `PUT` | `/notes/{note_id}` | Обновить заголовок и содержимое заметки | `200` |
| `DELETE` | `/notes/{note_id}` | Удалить заметку | `204`, без тела |

### Пример работы через curl

Зарегистрируйте пользователя:

```bash
curl -X POST http://127.0.0.1:8000/register \
  -H 'Content-Type: application/json' \
  -d '{"email":"user@example.com","password":"example-password"}'
```

Получите токен. Этот запрос принимает форму `application/x-www-form-urlencoded`:
email передаётся в поле `username`.

```bash
curl -X POST http://127.0.0.1:8000/token \
  --data-urlencode 'username=user@example.com' \
  --data-urlencode 'password=example-password'
```

Ответ содержит `access_token` и `token_type` со значением `bearer`.
Скопируйте `access_token` в переменную и создайте заметку:

```bash
TOKEN='вставьте-access_token-из-ответа'

curl -X POST http://127.0.0.1:8000/notes \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"title":"Первая заметка","content":"Текст заметки"}'
```

Получите список своих заметок:

```bash
curl http://127.0.0.1:8000/notes \
  -H "Authorization: Bearer $TOKEN"
```

В запросах создания и обновления `title` обязателен и должен быть непустым.
В базе заголовок ограничен 200 символами. Поле `content` необязательно и может
содержать строку или `null`. При `PUT` отсутствие `content` заменяет его на `null`.
Ответ с заметкой содержит `id`, `title`, `content`, `created_at` и `updated_at`.

Основные ошибки API:

- `400` — email уже зарегистрирован.
- `401` — неверные данные для входа, отсутствующий, некорректный или истёкший токен.
- `404` — заметка не существует или принадлежит другому пользователю.
- `422` — запрос не прошёл валидацию, например передан пустой заголовок или ID меньше 1.

## Тесты

Тесты проверяют регистрацию, вход, работу с JWT, хеширование паролей,
операции с заметками и запрет доступа к чужим заметкам.

Нужен запущенный PostgreSQL и отдельная база `notes_test`. Для базы из Compose
создайте её один раз:

```bash
docker compose exec postgres createdb -U root notes_test
```

Запустите тесты:

```bash
uv run pytest
```

Тестовое подключение использует хост, порт, пользователя и пароль из `DB_URL`,
заменяя имя базы на `notes_test`. Рабочая база в `DB_URL` должна иметь другое имя.
Тесты удаляют и создают таблицы в `notes_test`, очищают их перед каждым тестом
и удаляют после завершения сессии. Используйте эту базу только для тестовых данных.
Применять миграции к ней отдельно не требуется.

## Структура проекта

```text
backend/
  main.py          # FastAPI: маршруты API и раздача интерфейса
  config.py        # Настройки из окружения и .env
  database.py      # Подключение к БД и сессии SQLAlchemy
  models.py        # Модели User и Note
  schemas.py       # Схемы запросов и ответов
  security.py      # Хеширование паролей, JWT и текущий пользователь
frontend/
  index.html       # Веб-интерфейс с HTML, CSS и JavaScript
alembic/
  versions/        # Миграции схемы PostgreSQL
tests/             # Тесты API и функций авторизации
experiments/       # Отдельные эксперименты с asyncio и HTTP-запросами
src/lpr/           # Заготовка консольной команды lpr
docker-compose.yml # Локальный PostgreSQL
pyproject.toml     # Зависимости и настройки проекта
uv.lock            # Зафиксированные версии зависимостей
```

Команда `uv run lpr` пока выводит приветствие. Для запуска веб-приложения
используйте `uv run uvicorn backend.main:app --reload`.
